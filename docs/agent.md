## Agent 到底是什么

Agent 是能够自己调用工具、连续完成多步任务的 AI 助手。

你对普通聊天说“帮我写一段综述”，它往往只能根据当前对话和通用知识直接回答。你对接入 PaperPiggy 的 Agent 说同一句话，它可以：

1. 先检查知识库状态；
2. 检索相关文献；
3. 选择最值得精读的来源；
4. 读取带页码或章节位置的原文；
5. 核对引文和实质论断；
6. 生成综述、提纲或资料汇编；
7. 把成果保存到 Agent 交付物或综述库；
8. 记录资料缺口和下一步任务。

<div class="callout agent">
  <strong>PaperPiggy 是知识引擎，Agent 是操作它的研究助手。</strong> 建库完成后，日常使用不需要你记住每一个按钮和工具；把研究目标说清楚即可。
</div>

## 可以连接哪些 Agent

只要客户端支持 MCP，就可以连接 PaperPiggy。应用当前重点提供：

- **Claude Code**：应用内推荐的入门选项；
- **Codex**：同样可以接入；
- **其他支持 MCP 的客户端**：使用 Agent 页提供的通用配置。

Agent 使用的模型和账户由对应客户端决定。PaperPiggy 里的硅基流动 Key 主要服务于知识库检索和应用内辅助功能，两者不要混为一谈。

## 连接前检查

<ul class="checklist">
  <li>PaperPiggy 已经完成 Zotero 连接和第一版索引。</li>
  <li>Claude Code、Codex 或其他 MCP 客户端已经可以正常打开。</li>
  <li>你知道自己准备在哪个 Agent 客户端中使用知识库。</li>
</ul>

## 第一次验证

接入后，先做一个不写入内容的简单检查：

<div class="prompt">连接我的 PaperPiggy 知识库，先完整读取项目记忆，再查看知识库状态，然后搜索“一个确定存在于我文库中的主题”。告诉我你实际调用了哪些知识库能力，不要只用通用知识回答。</div>

正常情况下，Agent 会返回文献数量、索引或深索状态，并列出库内真实文献。

## 让助手复用专用浏览器

点击主界面顶部“打开专用浏览器”后，可以在正常浏览器窗口中登录研究需要的网站。再次点击会显示现有窗口，保留原标签。这个按钮只负责打开浏览器，投稿或周报仍需你另行交给助手。

助手和自动化工具应读取同一份浏览器关联，不能猜测或写死调试端口。已接入 MCP 的助手读取 `localkb://browser`；通过本机服务接入的工具读取 `GET /browser/config`。两者都返回同一个发现对象，其中 `endpoint` 是实际连接地址，`configured` 和 `running` 表示关联与运行状态；读取配置本身不会启动浏览器。关联文件位于应用数据目录的 `dedicated_browser.json`，与普通设置分开保存。

初次沿用已有 Chrome DevTools 连接时，PaperPiggy 会核对现有进程、程序路径、资料目录和端口。旧连接对应的浏览器尚未运行时，先按原来的方式打开它，再完成核验；助手不能为绕过提示另建资料目录。已保存端口被其他程序占用时，助手应报告冲突，不能接管其他浏览器、关闭程序或静默改端口。不同电脑可以使用相同端口，只需处理各自电脑上的占用。

手动点击按钮可以显示浏览器窗口；后台周报核查仍应保持后台运行，不激活窗口、不抢桌面焦点。开发测试必须使用单独的资料目录和测试端口，避免干扰正式浏览器。浏览器连接并不代表授权投稿、发布或执行其他账号操作，助手仍须遵守任务本身的授权范围。

### 进阶：让浏览器工具动态跟随关联

已经能连接浏览器的用户可以保留当前有效连接，直接使用顶部按钮。外部客户端中原来保存的连接设置不会被 PaperPiggy 自动改写；只有希望工具以后动态跟随 PaperPiggy 的浏览器关联时，才需要配置启动桥并重新连接。

PaperPiggy 随应用提供 `app/browser_devtools_mcp.py`。让助手读取本机服务 `GET /agent/mcp-config` 返回的 `browser_mcp_json`，使用其中已经填好本机真实路径的配置：命令指向应用自带的 `pythonw.exe`，参数依次为启动桥的实际路径、`--`、`npx`、`--no-install`、`chrome-devtools-mcp`。使用前应确认对应浏览器工具已经可用；启动桥不会安装工具。

启动桥只读取并核对同一份浏览器配置，再把实际地址以 `--browserUrl` 传给浏览器工具；它不会打开或激活浏览器。配置完成后按外部客户端的方式重新连接。后台自动化每次使用前仍应读取 `localkb://browser` 核对本次关联与运行状态，并保持不抢桌面焦点。这个进阶接入不影响手动点击“打开专用浏览器”。

## 项目记忆是跨 Agent 的接力点

`0_Agent资料库/记忆/项目记忆.md` 保存你的长期偏好、已定决策、关键进度和事实。每次任务开始，Agent 必须先完整读取它；未读时，PaperPiggy 会拒绝其他知识库工具。任务产生新的长期信息时，Agent 必须在结束前写回这里。

Claude Code、Codex 等客户端仍可以保留自己的 auto memory 或私有记忆，但这些内容只有原客户端能看到，不能替代 PaperPiggy 的项目记忆。凡把本项目的长期信息写进私有记忆，也必须把同一实质内容同步到项目记忆，这样换 Agent 后才能继续接手。

## 把官方法规原文加入独立法源库

需要研究现行法、司法解释或历史版本时，可以直接让 Agent 查找制定机关的官方网页，核对完整正文后加入 PaperPiggy。法规保存在独立本地目录，不会写入或修改 Zotero；建索引后，它与普通文献一起参与检索，也可以单独限定为“只检索法规”。

实际流程分两步：

1. Agent 提交法规全称、制定机关、通过/修订/施行日期、效力状态、官方 URL 和清理后的完整 Markdown 正文；还可以同时提交一段约 150 字的中文检索摘要；
2. PaperPiggy 先检查来源域名、正文长度、法规名称和条文结构；如果带了检索摘要，还会同时检查过短、乱码、连续重复和失控长文。预览会回显摘要字数和质检结果，**此时不会写入**；
3. 你核对预览并明确确认后，Agent 携同一份内容和确认令牌再次调用，才会原子写入并更新索引。

成功标志是 Agent 返回以 `STAT-` 开头的来源 key，并说明已开始增量建索引。随法规提交的摘要会进入同一检索摘要库并随条文一并嵌入；如果没有提交，法规仍会正常入库，但 Agent 会明确提示调用 `submit_agent_summaries` 补写，否则 `deep_status` 会把它统计为摘要缺失。此后可以说“只检索法规中关于……的条文”“读取该法第二十条”“按当前版本和条号生成引注”。如果正文、元数据或摘要在确认前发生任何变化，原令牌会失效，必须重新预览；重复入库不会覆盖既有摘要，非官方域名还需要额外明确确认。

## 不需要另外安装工作流

PaperPiggy 已经准备了六条开箱即用的工作流：

- 论文初稿（少年司法版）；
- 综述（少年司法版）；
- 论文初稿（通用暂用版）；
- 综述；
- 维护综述库；
- 跨学科发散与补文献。

Agent 会先判断任务是论文初稿还是综述，再按研究领域选择专用版或通用版。少年司法论文初稿会先完整精读本题核心文献，再参照 12 篇三大刊论文的实测结构搭骨架；骨架完成后先展示逐字标题树，并逐章说明回答什么问题、使用什么材料、得出什么判断。你没有异议，它就继续写全文，不停下来干等。读取这条工作流时只会自动附带《三大刊结构》台账；旧《成文技艺手册》不再分发，升级后会删除应用管理的现存副本。批量精读、引证核验和定稿前独立校核默认交给子代理并行完成，正文各章仍由同一 Agent 起草。最终论文固定交付经打开或渲染检查的 DOCX，Markdown 只能作为中间稿或核验记录。通用初稿目前仍会提示它尚未经过其他部门法的专项训练验证。

当你的请求与某条工作流匹配时，Agent 会先读取工作流再开始执行。工作流都是本机上的 Markdown 文件；在 Agent 页「专属资料库」卡片点击「打开技能文件夹」即可查看。以后可以直接与 Agent 商量修改，逐渐变成你自己的研究方法。自动附带的《三大刊结构》台账不是第七条工作流，也不会单独出现在工作流列表中。

默认写作和维护流程会先查看已有综述主题，优先充实现有页面并保持主题归类一致；文献 key 只用于内部核验和综述库来源追溯，论文、报告、表格等交付文件会改用作者、题名、年份和页码等人类可读引注。

## Agent 能改什么，不能改什么

Agent 可以：

- 检索和读取知识库；
- 在你确认预览后，把已核对的官方法规原文写入独立法规库；
- 发起增量建库、深索和检索摘要维护；
- 创建或更新由 Agent 维护的综述页；
- 建立知识页之间的链接；
- 标记可能过时的结论；
- 写入交付物、资料库和项目记忆。

Agent 不会：

- 修改 Zotero 中的原始条目和附件；
- 把法规静默写入 Zotero，或绕过预览确认覆盖既有法规版本；
- 删除原始文献；
- 通过 MCP 删除综述页；
- 直接覆盖你已经人工核验的知识页。

Agent 更新已核验页的正文、来源或互链时，只会提交一份不参与检索的待审稿；原核验版继续生效。你可以在应用中查看具体差异后接受并核验、先编辑或放弃。综述库还保留版本历史，已发布版本仍可回滚。

## 建议的第一次正式任务

<div class="prompt">围绕“我的当前课题”，先检查知识库覆盖情况，搜索相关文献并分组。只精读最相关的 5 篇，逐篇给出原文位置和核心论点；如果文献还未深索，先完成这 5 篇的深索和检索摘要。最后列出已有证据、相互冲突的观点和仍需补充的资料。</div>

这个任务能同时验证检索、深读、原文定位和检索摘要，也不会一开始就让整个大库长时间运行。
