## 先分清三种“更新”

| 操作 | 实际作用 | 什么时候使用 |
|---|---|---|
| 手动更新知识库 | 扫描 Zotero 或文件夹的新增和变化，补题录与语义索引 | 日常新增文献后 |
| 清空并从头重建索引 | 删除并重新生成索引产物 | 索引严重异常且普通更新无效 |
| 应用更新 | 把 PaperPiggy 程序升级到新版本 | 设置页提示有新版时 |

新增文献后先更新知识库，不需要重新安装应用。普通版本升级也不需要顺手清空索引。

## 配置两类独立备份

进入“设置 → 数据与维护 → 备份与恢复”，分别选择“小猪备份”和“Zotero 完整备份”。两类任务各自保存完整包，恢复一份不需要其他版本。

| 任务 | 保存什么 |
|---|---|
| 小猪备份 | 综述库、Agent 交付物与资料库、项目记忆、分类、人工修改等知识库资产；索引和 API 密钥按勾选保存 |
| 专用浏览器资料（小猪任务中的选项） | 默认勾选已关联专用浏览器的完整资料，包括登录记录、标签、插件、站点数据和配置，只排除明确可再生缓存；不收集其他日常浏览器 |
| Zotero 完整备份 | 所选数据目录与整个对应用户配置目录，包括题录、PDF 等附件、笔记、批注、分类、标签、引文样式、转换器、插件和设置，以及所选 profile 的关联信息 |

Agent 模板升级产生的 `0_Agent资料库/升级与备份/待合并/` 和 `历史备份/` 也会随小猪备份保存。它们与定期备份包的保留策略分开管理，不会被自动清理。

### 第一次设置

1. 点击“配置后台备份”，在 Windows 提示时确认管理员授权。此组件使用 VSS 同批卷快照读取已落盘内容；普通应用不整体提权，组件必要更新时也需确认。
2. 分别核对两类任务的来源和备份位置。Zotero 自动发现不准确时，可手动选择包含 `zotero.sqlite` 的数据目录及对应用户配置目录。
3. 选择间隔天数、执行时刻和保留份数。Zotero 默认保留 **2 份**，小猪沿用已有保留设置。目的地未选或组件未就绪时不能开启计划。
4. 保持“登录后补跑”开启，再保存并启用自动备份。即使小猪没有打开，后台也会执行；电脑关机错过的任务在下次登录 Windows 后补跑当前状态。
5. 先点“立即备份”，等待成功记录，再在列表点“校验与恢复…”核对内容。

成功标志是记录显示本次成功时间、包路径与校验结果。排队、正在打包以及上次尝试时间都不代表本次备份成功。

### 运行中备份与保留

不用为了备份退出 Zotero 或浏览器。后台从同一次卷快照读取文件，再校验文件清单、哈希、归档、数据库和附件覆盖；只能保存已经落盘的修改。快照或校验失败会记录原因，不降级为直接复制活动数据库，已有成功版本会保留。

每次先完成并校验新包，再清理本任务超出保留数的最旧成功版本。新包失败不会先删旧包；旧版清理失败会单独提示，新成功版本仍保留。现有“过时备份”、其他任务或其他电脑的文件，以及手工放入的旧包不会被接管或自动删除。保留 2 份仍须为创建中的第 3 份预留空间。

页面可查看下次时间、任务阶段与持久记录；可以停止正在创建的备份，恢复不能中途停止。关闭自动开关仅影响今后的触发，不取消当前任务。

备份包**不加密**，用户配置可能含插件密钥或登录会话，请保护存放位置。浏览器原有加密文件会保留，不会解密导出密码。云盘请同步已完成的静态备份包，不要同步正在读写的整个数据库目录；同一块硬盘上的副本也不能防止整盘故障。

## 怎样恢复

先核对包的时间和范围，优先选择“恢复到新目录验证”。这会保留当前来源，便于检查题录、附件、笔记、批注、插件设置、综述和 Agent 成果。不要把“文件已解压”当作已完成应用内核对。

需要原位恢复时，逐项确认目标目录，保存当前成果并自行退出相应的 Zotero 或专用浏览器。小猪不会强制结束进程。恢复小猪自身还须先断开使用它的 MCP 连接，再退出小猪；后台完成前不要重新打开。浏览器页面关闭不代表小猪后台服务已经退出。

恢复会先检查包的完整性和安全性，并在暂存区校验；替换前保留当前目录作为单独的**恢复回退件**。这些回退件不计入常规保留数量，由你确认无误后手动清理。失败时查看持久记录，不要自行混合新旧目录。

Zotero 恢复后保持备份中的**原自动同步设置**。后续同步可能再次应用云端较新的修改或删除，请先核对恢复结果；恢复不会自动替换云端库。

浏览器热备恢复后，首次打开专用窗口可能提示“恢复上次会话”。请你在这个窗口自行核对并确认，再检查标签、站点和登录状态；恢复成功不等于已经完成这些人工核对。

重装系统或换机时，核对 Zotero 版本、数据目录与 profile 关联；含浏览器资料的包还需填写本机已安装的同类浏览器程序路径，不会把 Chrome 资料自动切换给 Edge。Windows、浏览器及网站规则可能令旧登录失效，必要时重新登录。应用不会自动安装浏览器、开启云同步或提取密码。

旧格式小猪包仍可从“旧版小猪备份”查看、校验和恢复，内容以原清单为准；它不含 Zotero 完整库和浏览器登录资料，也不受新任务自动清理。

## 应用更新

设置页的“应用更新”可以检查、下载并应用新版。更新程序不会把知识库数据当作替换目标。

下载完成后，PaperPiggy 会核对官方 SHA-256、完整文件清单和每个文件的哈希；损坏、被篡改、缺文件或多出意外文件的更新包会被拒绝。新版先在临时区域验证，成功后才替换应用代码；失败时会回滚，用户自行修改过的旧代码和失败现场会保留。

应用还会分别核对题录、全文切块和语义向量的稳定生成契约。普通错误提示、重试或界面改动不会再被当成“索引规则变化”；兼容升级会自动登记，不要求清空索引。只有产物规则或检索引擎确实不兼容时，应用才会说明具体原因并提示相应处理。

如果应用内更新失败，可以从 [GitHub Releases](https://github.com/DrinkTea905/paper-piggy/releases/latest) 下载最新安装器，直接覆盖原安装位置，不必先卸载。

## 专用浏览器的关联与登录资料

应用升级和“恢复默认设置”会保留专用浏览器关联；专用浏览器的资料目录也会继续使用。已经有专用浏览器的用户不需要迁移或重建登录资料，新用户第一次在独立浏览器中登录需要的网站即可。

小猪备份默认勾选专用浏览器的完整资料，只排除明确可再生的缓存；可在任务中关闭该选项。旧格式小猪包不含浏览器登录资料。新包恢复到另一台电脑后，受 Windows、浏览器加密绑定和网站规则影响，仍可能需要重新登录。备份包不加密，请保护存放位置；恢复应按上文步骤核对目标，不要随意移动或覆盖正在使用的浏览器资料。

## 删除同步与清理

开启删除同步或手动清理已删除文献时，PaperPiggy 会先预览预计处理数量，再要求二次确认。它只清理 PaperPiggy 自己的索引记录，不会删除 Zotero 条目或原始文件。

如果一次预计清理超过 20 篇，或超过当前文库的一半，操作会自动中止。先检查 Zotero 或受管文件夹是否暂时无法读取，不要在来源异常时强行清理。

## 常见问题

### 专用浏览器提示端口被占用

应用会保留已经保存的端口，并明确提示占用冲突，不会自动关闭占用程序、接管其他浏览器或换一个端口。先保存其他程序里的工作，再确认提示所指向的占用情况；如果需要关闭程序，由你自行决定。处理完成后，再点击“打开专用浏览器”。

不同电脑使用同一个端口互不影响；同一台电脑的开发测试应使用单独端口和资料目录。

### 升级后首次打开专用浏览器需要做什么

已经有专用浏览器的用户，先按原方式打开原浏览器，再点击顶部“打开专用浏览器”，让应用核对并保存原有关联。原程序、资料目录、端口和登录资料会继续使用；原有标签也会保留。

此前没有专用浏览器的用户，直接点击按钮。应用自动选择 Chrome 或 Edge、建立独立资料目录并在核验后保存关联；在打开的窗口中登录需要的网站即可。如果没有安装支持的浏览器，应用会提示，由你自行安装后重试。

### 硅基流动 Key 测试失败

依次检查：

1. 是否使用了正确账户创建的 Key；
2. <code>.cn</code> 与 <code>.com</code> 是否混用；
3. 账户是否完成实名认证；
4. 余额是否为零；
5. 网络能否访问硅基流动。

如果返回余额不足，即使模型标记为免费，也先充值 1 元再测试。

### Zotero 没有被自动识别

在 Zotero 的“首选项 → 高级 → 文件和文件夹”中查看数据目录，把包含 <code>zotero.sqlite</code> 的目录手动填入 PaperPiggy。

### Zotero 新文献没有出现

先点击“手动更新知识库”。题录会先出现，语义索引随后在后台完成；深索仍需要按优先级另行处理。

如果提示有任务正在运行，先看提示中的具体类型：全文深索、Agent 写入、索引维护需要等待；后台备份可到“设置 → 数据与维护 → 备份与恢复”查看进度或停止；数据恢复不能中途停止。没有真实任务却仍持续提示忙碌时，先升级并重启到最新版，再重试。

### 文献能看到，但 Agent 读不到正文

这通常表示只有题录，尚未深索。让 Agent 查看该文献状态，并完成深索和检索摘要。

<div class="prompt">检查《文献标题》的题录、全文附件、深索和检索摘要状态。能自动处理的直接完成；如果附件丢失、损坏或格式不支持，告诉我具体原因。</div>

### 扫描版 PDF 深索很慢

PaperPiggy 会自动在本机 OCR 没有文字层的页面。OCR 比普通文本提取慢得多，属于正常现象。可以先处理当前课题的重要文献，其余安排在电脑空闲时运行。

### 检索结果找不准

让 Agent 先检查：

- 语义索引是否完成；
- 关键文献是否已经深索；
- 检索摘要是否有效；
- 当前查询是否过宽或过窄；
- 是否需要限定 Zotero 分类、年份或来源类型。

不要第一反应就清空索引。

### Agent 看不到 PaperPiggy

回到应用的“Agent”页，重新复制对应客户端的接入命令。执行后重新打开 Agent 会话，再让它查看知识库状态。

### Agent 能连接，但只凭通用知识回答

在任务中明确要求它先检查 PaperPiggy 状态、检索库内文献并给出原文位置。也可以直接说：

<div class="prompt">这项任务必须使用我的 PaperPiggy 知识库。先调用知识库检查和检索能力，再回答；库内没有证据时请明确说没有，不要用通用知识补齐。</div>

### 深索全库要多久

时间取决于文献数量、文件大小、扫描件比例和电脑性能。几百到上千篇文献可能需要数小时甚至更久。先按课题分批处理，再利用夜间空闲时间补齐。

### 什么时候才需要清空重建

只有以下情况才考虑：

- 应用明确提示索引异常；
- 重复或错误索引无法通过普通更新修复；
- 更换了不兼容的检索引擎；
- 版本说明明确要求。

普通应用升级、错误提示文字变化或网络重试改进不属于重建理由。执行前先创建备份，并先阅读应用显示的具体契约差异。

## 需要报告问题时

在 [PaperPiggy 主仓库 Issues](https://github.com/DrinkTea905/paper-piggy/issues) 提交应用问题，在 [教程仓库 Issues](https://github.com/DrinkTea905/paper-piggy-guide/issues) 反馈教程问题。

为了更快定位，请说明：

- PaperPiggy 版本；
- Windows 版本；
- 使用 SiliconFlow 云端检索还是本地检索；
- 使用 Zotero 还是文件夹模式；
- 发生问题前执行的步骤；
- 完整报错文字；
- 已经尝试过哪些处理。
